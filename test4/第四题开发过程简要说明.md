# 开发过程简要说明 — 模拟风扇（第四题）

> 考核题：软件第四题《模拟风扇》
> 目标：电机主轴装扇叶当风扇，10k 电位器当旋钮；ADC 读旋钮 → 目标值；PID 实现**定速 + 定位**控制；
> VOFA+ 展示调参过程；整体用 **FreeRTOS** 开发。
> 本说明对应工程目录 `test4/`（CubeMX + CMake + HAL + FreeRTOS CMSIS_V2）。

### 2.3 接线要点

```
TB6612:  VM ← 降压模块 7.4V      VCC ← 3V3        GND ← 公共地（粗线直回降压模块）
         AIN1←PB0   AIN2←PB1    PWMA←PB6         STBY←PB5(或直接 3V3)
         AO1 → 电机 M+            AO2 → 电机 M-

电机:    VCC ← 3V3（编码器供电，就近并 0.1µF）   GND ← 公共地
         A → PA6                B → PA7          （A/B 接反会导致反馈符号反向，见 §7-8）

电位器:  一端 → 3V3   中间(滑臂) → PA1   另一端 → GND
```

**TB6612 真值表（STBY=1 时）**：`AIN1=1,AIN2=0` 正转；`AIN1=0,AIN2=1` 反转；`00` 停止(滑行)；`11` 刹车。

> ⚠️ 易错点：`VM` 是电机功率电源（接 7.4V），`VCC` 是芯片逻辑电源（接 3.3V，**绝不能接 7.4V**）；`STBY` 悬空会导致电机完全无反应。

### 2.4 供电方案（电机 7.4V 与逻辑 5V/3.3V 必须分开）

```
12V 电池 ──> 降压模块(带载调到 7.4V) ──> TB6612 VM
            降压 OUT- ──┬─> TB6612 GND（粗线，电机电流直接回降压模块）
                        └─> 蓝丸 GND（信号参考）
Micro-USB 充电线 ──> 手机充电头/充电宝(5V) ──> 蓝丸（逻辑供电）
蓝丸 3V3 ──┬─> TB6612 VCC
           ├─> 编码器 VCC
           └─> 电位器一端
```
- **TB6612 的 GND 必须用粗线直接回降压模块**：电机电流（1~2A）走"降压→VM→电机→TB6612 GND→降压"短回路；若只经蓝丸地或电脑 USB 地回流，会污染地线，导致编码器计数乱跳、ADC 抖动甚至复位。
- 电机线（M+/M-）与编码器线（A/B）**分开走线**；`VM` 旁并 100µF + 0.1µF。

## 3. CubeMX 配置

### 3.1 时钟
`RCC → HSE = Crystal/Ceramic Resonator`；`Clock Configuration` 里 **HCLK 输入 72** 让 CubeMX 自动解算：
HSE 8MHz → PLL×9 → SYSCLK **72MHz**，AHB /1，**APB1 /2（36MHz）**，APB2 /1。

### 3.2 外设

| 外设 | 配置 | 说明 |
|---|---|---|
| TIM3 | **Encoder Mode**，ARR=65535，PSC=0，`Encoder Mode TI1 and TI2` | 硬件四倍频计数，无需中断 |
| TIM4 | CH1 **PWM Generation**，**PSC=0 / ARR=3599**，PWM mode 1，Pulse=0 | 72MHz/3600 = **20kHz**，占空比 3600 级分辨率 |
| ADC1 | IN1(PA1)，Continuous Conversion = **Enable**，12bit，采样 **71.5 Cycles** | 旋钮采样 |
| USART1 | Asynchronous，115200 | VOFA+ |
| GPIO | PB0/PB1 输出、**PB5 输出初值高**、PC13 输出、PA0 输入上拉 | — |
| SYS | Debug = Serial Wire；**Timebase Source = TIM1** | Timebase 必须避开 TIM3/TIM4 |

### 3.3 FreeRTOS（Middleware → FREERTOS）

| 项 | 设置 | 理由 |
|---|---|---|
| Interface | **CMSIS_V2** | 用 `osThreadNew / osMessageQueueNew / osMutexNew` 等 V2 API |
| `TICK_RATE_HZ` | **1000** | 1ms 节拍，控制环 1ms 分辨率 |
| `configUSE_PREEMPTION` | Enabled | 抢占式，保证控制环按时执行 |
| `configUSE_MUTEXES` | Enabled | 串口/遥测互斥 |
| `CHECK_FOR_STACK_OVERFLOW` | Enabled (Method 2) | 调试期抓栈溢出 |
| `TOTAL_HEAP_SIZE` | **8192** | 5 个任务 + 软件定时器任务的余量（F103C8 共 20KB） |
| Tasks and Queues | 保留默认 `defaultTask`，不在此加任务 | 应用任务全部在代码里创建，见 §4.3 |
| `USE_NEWLIB_REENTRANT` | **不开**（CubeMX 会提示，但只是提示） | 每个任务可省 ~1KB RAM；代价是不能多任务随意 `printf`，本工程串口输出集中在 `VofaTask` |

> 说明：`USE_TIMERS` 在 CMSIS_V2 下被 CubeMX 锁为 Enabled（只读，改不了），因此软件定时器任务会固定占用约 1.4KB RAM，靠把堆调到 8192 解决。

### 3.4 工程生成
`Toolchain/IDE = **CMake**`（配合 VS Code 的 STM32Cube 插件编译）；勾选"每个外设生成一对 .c/.h"与"Keep User Code"。

## 4. FreeRTOS 设计（本题重点）

### 4.1 任务划分

| 任务 | 优先级 | 栈(字) | 周期 | 职责 |
|---|---|---|---|---|
| `MotorCtrlTask` | **osPriorityHigh** | 192（768B） | **1ms**（`osDelayUntil`） | 读编码器增量 → 算转速/角度 → 跑 PID → 输出 PWM → 更新遥测 |
| `KnobTask` | osPriorityAboveNormal | 128 | 20ms | 读 ADC → 8 次平均 + 一阶低通 → 通过队列发百分比 |
| `VofaTask` | osPriorityNormal | 160 | 20ms | 组 JustFloat 帧（5 通道）→ 互斥锁保护下发串口 |
| `KeyTask` | osPriorityBelowNormal | 128 | 20ms | 扫 PA0（60ms 消抖）→ 切换定速/定位，并请求复位 PID 与角度基准 |
| `StartDefaultTask` | osPriorityNormal | 128 | 心跳 | CubeMX 生成的 defaultTask，本工程复用为**心跳灯**：定速闪 1 次 / 定位闪 2 次 |

**优先级原则**：周期越短、越不能延迟的任务优先级越高 → 1ms 控制环最高，LED 最不重要。

### 4.2 任务间通信

| 机制 | 用在哪 | 代码 |
|---|---|---|
| **消息队列**（深度 1） | `KnobTask` → `MotorCtrlTask` 传旋钮百分比 | `osMessageQueuePut/Get(q, &pct, 0U, 0U)` |
| **互斥锁** | 1) 遥测结构体（控制环写、上报任务读）2) 串口发送（避免多任务数据交叉） | `osMutexAcquire(..., osWaitForever)` … `osMutexRelease` |
| **`osDelayUntil`** | 控制环节拍 | `tick += CTRL_PERIOD_MS; osDelayUntil(tick);` |

**为什么控制环必须用 `osDelayUntil` 而不是 `osDelay`**：`osDelay(1)` 只保证"至少等 1ms"，加上执行时间会让周期越来越长，PID 的采样周期变成不定值，参数就白调了。

### 4.3 任务/对象创建位置（重新生成代码不丢失）

- `main()` 的 `USER CODE 2`：`app_peripherals_init()`（启动编码器/PWM/ADC）
- `freertos.c` 的 `MX_FREERTOS_Init()` → `USER CODE BEGIN RTOS_QUEUES`：`app_rtos_objects_init()`（建队列+互斥锁）
- `freertos.c` → `USER CODE BEGIN RTOS_THREADS`：`app_rtos_tasks_create()`（建 4 个应用任务）
- `freertos.c` 的 `StartDefaultTask()` 内：`led_task(argument);`

以上全部写在 CubeMX 生成的 `USER CODE` 区块内，**CubeMX 重新生成代码时不会被覆盖**。

### 4.4 不开 `USE_NEWLIB_REENTRANT` 的规避做法

| 不允许多任务随意用 | 本工程做法 |
|---|---|
| `printf` / `puts`（走 stdout FILE） | 串口输出集中在 `VofaTask`；JustFloat 用 `memcpy` 直接组包，**不需要 printf** |
| `malloc` / `free` | 全部静态数组；FreeRTOS 对象在初始化阶段一次性创建 |
| `strtok` / `setlocale` | 不使用 |

### 4.5 数据流

```
旋钮 ─ADC─> KnobTask ─队列─> MotorCtrlTask(1ms, PID) ─PWM─> TB6612 ─> 电机 ─> 扇叶
编码器(TIM3 硬件计数) ─────> MotorCtrlTask
MotorCtrlTask ─遥测(互斥锁)─> VofaTask ─USART1─> VOFA+
KeyTask ─切模式─> 共享状态 s_mode
```

## 5. PID 设计与实现

### 5.1 量纲（贴出来是为了让调参有依据）

| 项 | 定速环 | 定位环 |
|---|---|---|
| 目标/反馈单位 | RPM | 度(°) |
| PID 输出单位 | **占空比千分比**（-1000~+1000，1000 = 100%） | 同左 |
| 控制周期 | 1ms | 1ms |

### 5.2 关键实现点（`pid.c`）

1. **条件积分抗饱和**：只有"输出未顶到限幅"或"误差方向能让它退回来"时才累加积分。否则启动瞬间误差巨大、输出已饱和在 ±1000，积分会一路涨到顶，到目标后要靠反向误差慢慢泄放 → 造成大超调。
2. **微分作用在测量值上**（而非误差上）：避免设定值阶跃时的"微分冲击"；再经一阶低通（α=0.3）抑制编码器量化噪声。
3. **积分限幅**：积分项单独限幅到输出范围。

### 5.3 电机死区补偿（`motor.h` 的 `MOTOR_DEADZONE = 150`）

电机有启动死区：占空比太小时不转，PID 会永远调不到目标。做法：当 PID 输出方向明确但幅值落在死区内时，抬到最小可转占空比（±150‰）。

### 5.4 两种模式的差异（这里踩过一个真实 bug）

- **定速模式**：目标为 0 时直接停机（避免死区补偿在零速附近引起嗡嗡抖动）。
- **定位模式**：目标 0° 表示"转到 0°"，**必须让 PID 转回去**，不能停机；同时为避免在目标附近因死区补偿反复启停，设置 **±3° 到位死区**（进入死区输出 0，保持不动）。

> 最初代码把"目标≤0.5 就停机"这条规则写成了不分模式，导致**定位模式下目标回 0 时电机不转回**（角度卡死在 151°、PWM 恒为 0）。这是本项目最有价值的一个排查（详见 §7-11）。

## 7. 开发过程与问题排查（真实记录）

### 1) 生成工程工具链选成了 STM32CubeIDE
- 现象：VS Code 的 STM32Cube 插件按 CMake 工程构建，CubeIDE 工程（只有 `.cproject`）构建不了。
- 解决：`Project Manager → Toolchain/IDE` 改成 **CMake**，重新生成。

### 2) 时钟没配：SYSCLK 实际只有 8MHz
- 现象：`SystemClock_Config()` 里是 `RCC_OSCILLATORTYPE_HSI` + `PLL_NONE` + `SYSCLKSOURCE_HSI`；`.ioc` 里 `APB1Freq_Value=4000000`。
- 影响：PWM 频率、控制周期、串口波特率全部偏离设计值。
- 解决：`Clock Configuration` 页把 **HCLK 输入 72** 让 CubeMX 自动解算（HSE + PLL×9 + PLLCLK）。

### 3) TIM4 只改了 Prescaler，Counter Period 仍是 65535
- 现象：`htim4.Init.Period = 65535` → PWM 只有 **1.1kHz**（若 Prescaler 也保持 71 则只有 15Hz），电机啸叫、PID 粗糙。
- 解决：**PSC=0、ARR=3599** → 20kHz，且占空比有 3600 级分辨率。

### 4) 工程多套一层目录 → CMake 插件报错
- 现象：`工作区文件夹 d:/Projecttest/test4 包含多个 CMake 项目`。
- 原因：工作区根下没有 `CMakeLists.txt`，真正的工程在子目录 `test4/test4/`。
- 解决：把工程整体提上一层，使 **工作区文件夹 = 工程根**（与 test2/test3 结构一致）。

### 5) 未配置就先构建 → `build/Release is not a directory`
- 解决：任务拆成 `1. Configure (Release)` → `2. Build (Release)` → `3. Flash`，并把 `Build & Flash` 串成 1→2→3 顺序执行。

### 6) 烧录脚本报 PowerShell 语法错误（意外的标记 `}`）
- 原因：脚本里写了**中文注释**且文件是 UTF-8 **无 BOM**；Windows PowerShell 5.1 会按系统 ANSI(GBK) 解码 `.ps1`，中文变乱码后把大括号解析坏了。
- 解决：`.ps1` 一律**纯 ASCII**（英文注释）。同类问题也解释了为什么之前的脚本一直正常（原脚本就是纯 ASCII）。

### 7) 旋钮无反应：目标恒定 260
- 现象：VOFA+ 通道0 恒定 260（= 旋钮 43.3% = ADC≈1774 = **PA1 电压 ≈1.43V**，正好在 3.3V 中点附近，是**引脚悬空**的典型值）。
- 原因：电位器滑臂到 PA1 的那根杜邦线**内部断线**。
- 解决：量电位器中间脚电压（旋转时应 0→3.3V 平滑变化）→ 换线后正常。
- 教训：**先量电压再怀疑代码**。

### 8) 编码器符号反：目标为正、实际恰好是其负数
- 原因：编码器 A/B 接线与"正 PWM 方向"的对应关系反了。
- 解决：在 `encoder.h` 里把 `ENCODER_SIGN` 改成 **-1**（等价于对调 A/B 两根线），随后通道1 变正并正常跟随。

### 9) "角度"看不到：通道1 在定速模式下是转速
- 原因：通道1 的含义随模式变化（定速=转速 RPM，定位=累计角度°），标定 CPR 时看不到角度。
- 解决：新增 **通道4 = 累计角度(°)**，任何模式下都上报，标定 CPR 不用切模式。

### 10) CPR 标定
- 方法：旋钮拧到最小（目标 0，电机不抢）或直接拔掉 `VM` → 手把输出轴**正好转一圈** → 读通道4。
- 数据：通道4 显示 **430°**（当时 CPR 填的是 880）→ 真实 **CPR = 430 × 880 ÷ 360 ≈ 1051** → 填回后复测一圈 ≈360° ✅。
- 影响：CPR 偏小会让转速读数虚高（1051/880 ≈ 1.19 倍），PID 实际工作在一个错误标定的量纲上。

### 11) 定位模式"到 0° 不回转"（功能 bug）
- 现象：角度卡死在 151°、PWM 恒为 0；目标在 0/150 之间跳但电机不动。
- 原因：`app.c` 里"目标 ≤0.5 则停机"的规则**没有区分模式**，定位模式下被错误地当成停机条件。
- 解决：该规则**仅对定速模式生效**；定位模式改用 **±3° 到位死区**。
- 修复后：定位阶跃一次通过（见 §8）。

### 12) 关于 Flash 容量的一次误判（自查纠正）
- 我早期用临时命令验证体积时**漏了 `-ffunction-sections -fdata-sections`**，导致 `--gc-sections` 无法裁掉未用到的 HAL 代码，得出"Debug 会溢出 64KB"的错误结论。
- 补上后实测：**Debug(-O0) 32384 B（49.4%）、Release(-Os) 19844 B（30.3%）**，两种预设都能编过。

### 13) 自动化调参中的环境限制与绕行
- 现象：本环境里 `ninja` 在启动编译器时挂死（管道捕获子进程输出的限制），CMake 的编译器探测同样会卡住。
- 绕行：`tools/build_cli.ps1` **直接调用 `arm-none-eabi-gcc`** 编译+链接（45 个文件约 10 秒），产出 `build/cli/test4.elf` 再交给 OpenOCD 烧录。

## 8. PID 整定过程与结果

### 8.1 让整定可自动化：自动阶跃测试模式 + 采集脚本

旋钮阶跃需要人工拧，无法无人值守复现，因此在 `app.h` 加了测试开关：

```c
#define APP_AUTO_STEP   1          /* 1=忽略旋钮，目标自动做 0 ↔ AUTO_STEP_LEVEL 方波 */
#define AUTO_STEP_LEVEL 150.0f     /* 定速=RPM，定位=度 */
#define AUTO_STEP_MS    3500u      /* 半周期 */
#define APP_START_MODE  CTRL_MODE_SPEED   /* 可直接选定位模式 */
```

配合 `tools/measure_step.ps1`：打开串口采 25 秒 → 解析 JustFloat 帧 → 自动识别阶跃 → 计算
**超调量 / 上升时间 / 调节时间 / 稳态误差 / 峰值 PWM**，并给出调整方向。
`tools/round.ps1` 把"编译→烧录→采集→评价"合成一条命令，**一轮约 1 分钟**。

> 评价脚本也曾有一个 bug：窗口取到"下一个上升沿"，把随后的下降段算了进去，导致"稳态值"取到停转后的 0。已改为**目标跌回 0 即结束窗口**。

> 附：调参过程的 VOFA+ 截图见工程根目录 **`调pid.jpg`**。

### 8.2 整定记录（6 轮）

| 轮次 | 参数 | 结果 | 结论 / 下一步 |
|---|---|---|---|
| R1 | Kp=5, Ki=0, 目标250 | 静差 **−80RPM**、超调 8.8%、**PWM 饱和 1000** | 满占空比实测仅 **185RPM** → **250 目标不可达**，降到 150；Kp=5 不振荡，可留 |
| R2 | +Ki=4 | 静差 −28.9RPM、超调 9.7%、PWM 751 | 积分有效但收敛慢（窗口不够） |
| R3 | Ki=8 | 静差 **−3.0RPM(2%)**、超调 9.5%、上升 540~640ms | 静差解决；上升偏慢，PWM 峰值 751 有余量 → 加 Kp |
| R4 | **Kp=10**, Ki=8 | **上升 40~140ms、超调 6.8%、静差 2%**、PWM 1000(加速段) | ✅ **定速环定稿** |
| R5 | 切定位模式 | 角度卡死 151°、PWM 恒 0 | 定位模式下"target=0 当成停机"的 bug |
| R6 | 修 bug 后（Kp=6,Ki=1,Kd=0.1） | **到位 ±1.7°、超调 2.4%、上升 120ms、调节 180ms** | ✅ **定位环定稿** |

### 8.3 最终参数

```c
/* 定速环 */ PID_SPEED_KP = 10.0   PID_SPEED_KI = 8.0    PID_SPEED_KD = 0.0
/* 定位环 */ PID_POS_KP   = 6.0    PID_POS_KI   = 1.0    PID_POS_KD   = 0.1
/* 量程   */ SPEED_MAX_RPM = 180   ANGLE_MAX_DEG = 360
/* 其他   */ MOTOR_DEADZONE = 150  ENCODER_CPR = 1051     ENCODER_SIGN = -1
```

### 8.4 调参中的三个工程体会

1. **先看 PWM 有没有饱和**：R1 的"静差"里有一半是"物理上到不了"，不先排除就会误加积分。
2. **积分收敛需要时间**：评价窗口必须长于积分建立时间，否则"静差"其实是"还没调完"。
3. **微分不是万能的**：转速由 1ms 编码器增量算出，低速量化噪声大（150RPM 时 1ms 仅约 2.6 个计数），加 D 只会放大噪声，所以速度环 Kd=0；位置环的 D 本质是速度阻尼，量纲是"度/秒"，只能给很小的值（0.1）。

## 9. 验证结果

| 验证项 | 实测 |
|---|---|
| 电机空载/带扇叶最大转速 | 满占空比约 **185 RPM**（7.4V） |
| 定速阶跃（0→150RPM） | 上升 **40~140 ms**，超调 **6.8%**，稳态误差 **≈2%（±3 RPM）** |
| 定位阶跃（0→150°） | 上升 **120 ms**，调节 **180 ms**，超调 **2.4%**，到位 **±1.7°** |
| 抗积分饱和 | 启动段 PWM 饱和 1000 时不再累积积分，到目标后无大超调 |
| 死区补偿 | 小输出抬到 ±150‰ 后电机可靠起转，低速不"卡死" |
| 控制周期 | `osDelayUntil` 严格 1ms，不受其他任务影响 |
| VOFA+ 上报 | 5 通道 50Hz（20ms/帧）稳定，无数据交叉 |
| 资源占用 | **Flash 19876 B / 64KB（30.3%）**，**RAM 13640 B / 20KB（66.6%）** |
| 角色/模式切换 | 按 PA0 切换，LED 定速闪 1 次 / 定位闪 2 次 |
| 编码器标定 | 手转一圈通道4 ≈ 360°（CPR=1051） |
