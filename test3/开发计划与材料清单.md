# 第三题《CAN 通信》— 材料清单与开发流程

> 考核题：软件第三题《CAN 通信》
> 目标：用模块化思路写 `can.c` / `can.h` 通用 CAN 收发函数，两块开发板分别作主机/从机，
> 主机按键触发发送 `0x11`，从机收到后返回 `0x22` 并翻转 LED，主机收到 `0x22` 后串口打印。
> 本文件是**动手前的材料与流程计划**；实现完成后再补写《第三题开发过程简要说明》（含实测结果与问题排查记录）。

### 2.2 选配（有则更稳）

| 物品 | 作用 |
|---|---|
| 万用表 | 量 CANH/CANL 静态约 2.5V、显性差分约 2V；量 5V 供电 |
| 示波器 | 看差分波形与波特率，定位"发不出/收不到" |
| 0.1µF + 10µF 电容 | 给 CAN 模块 VCC 就近退耦 |

> **关于野火 CAN 模块**：野火官方 CAN 例程（[F103 霸道 CAN 通讯实验](https://doc.embedfire.com/mcu/stm32/f103badao/std/zh/latest/book/CAN.html)）里每个节点各带一个 120Ω 端电阻，两个节点刚好构成总线两端的两个端电阻，符合 ISO11898 高速闭环网络要求。模块丝印可能是 `TXD/RXD` 或 `CTX/CRX`，也有带 `S/STB`（待机）引脚的版本——**待机脚必须接 GND 才进入正常工作模式**，接线前先看模块丝印。

### 2.3 你手上的模块：野火小智【CAN收发器】模块

| 项目 | 内容 |
|---|---|
| 型号 | 野火小智【CAN收发器】模块（CAN 总线电平收发，半双工、多机通信，**配源码**） |
| 官方资料页 | [野火小智【CAN收发器】模块](https://doc.embedfire.com/products/link/zh/latest/module/other_module/ebf_ebf_can_transceiver.html) |
| 资料云盘 | 百度网盘 [链接](https://pan.baidu.com/s/1ljNY4CvOsBmnBxxpBQHBPw?pwd=rk2f) 提取码 `rk2f`（含模块原理图/引脚图 + 配套源码） |
| 收发器 | 高速 CAN 收发器（野火 CAN 文档以 **TJA1050** 为主，具体型号以模块丝印为准），5V 供电，最高 1 Mbps |
| 角色 | TTL 侧接 MCU 的 CAN_TX/CAN_RX；总线侧接 CANH/CANL，与另一模块对接 |

**模块丝印（实物确认：`VIO / 5V / GND / TXD / RXD`）**：

| 位置 | 丝印 | 说明 |
|---|---|---|
| 排针（TTL 侧） | `VIO` `5V` `GND` `TXD` `RXD` | `VIO`→MCU 的 3V3（逻辑参考，必接）；`5V`→5V；`GND`→GND；`TXD`→MCU 的 CAN_TX；`RXD`→MCU 的 CAN_RX |
| 顶部 3 孔蓝色端子（总线侧） | `CANH` `CANL` `GND` | 接 CAN 总线：CANH↔对端 CANH、CANL↔对端 CANL；GND 两模块互连 |
| 板载指示 | `LED1` 等 | 收发状态/电源指示灯，调试时判断模块是否在动 |
| 电阻 | R1/R2 + 上拉 | 收发器外围，一般是板载端电阻与偏置 |

丝印要点（决定能不能通）：

1. **`VIO` 必须接 3.3V**（蓝丸 3V3），它是逻辑电平参考；不接或误接 5V → 逻辑侧不工作/电平判错 → 帧发不上总线 → **Bus-Off**；
2. TTL 侧是 `TXD/RXD`，**MCU 的 TX 接模块的 TXD**（接反是最常见的"发不出"）；
3. 总线侧 3 孔端子，**CANH 接 CANH、CANL 接 CANL**（两模块一样，顺序一致即可）；
4. 是否板载 120Ω（看 R/R2 和是否有跳帽）—— 两个模块各留一个，正好是总线两端。

> 野火官方论坛提醒：野火开发板上 CAN 收发器有**独立的供电跳线帽**，不接跳线帽收发器不上电，表现为"程序正常但总线上什么都没有"（[来源](https://www.firebbs.cn/forum.php?mod=viewthread&tid=12444)）。小智模块自带 VCC 供电，接线后仍务必用万用表量一次模块 VCC 是不是真的有 5V。

## 3. 硬件连接

### 3.1 单节点：开发板 ↔ CAN 模块

| 开发板引脚 | CAN 模块引脚 | 说明 |
|---|---|---|
| PA12（CAN1_TX，默认） | TXD | 复用推挽输出（**无需重映射**） |
| PA11（CAN1_RX，默认） | RXD | 上拉输入 |
| **3V3** | **VIO** | 逻辑电平参考，**必接**；不接/误接 5V → 发不上总线 → Bus-Off |
| 5V | 5V | TJA1050 是 5V 器件 |
| GND | GND | 必须共地 |
| — | CANH / CANL / GND | 接总线（下节） |

**引脚选择（小蓝丸 = STM32F103C8T6）**：CAN1 默认引脚是 **PA11(RX) / PA12(TX)**，**不需要重映射**，直接用最省事。小蓝丸的 PA11/PA12 在板子上连到 Micro-USB 的 D-/D+，但我们不用 USB（烧录走 ST-Link/SWD，串口走 PA9/PA10），所以这两个脚空着当 CAN 用没有影响。

- **备选**：若以后要保留 USB 功能，再改 **PB8/PB9 + 重映射**。但注意部分小蓝丸版本在 **PB9 焊了红外接收头（VS1838）**，会往总线上加负载，可能干扰 CAN 发送，所以主推 PA11/PA12。

**对应位时序里 CAN 外设时钟**：bxCAN 挂在 APB1（36MHz），无需额外配置。

### 3.2 总线：两个节点互联

```
  主机板                    CAN 总线                   从机板
 ┌────────┐                                            ┌────────┐
 │STM32F103│               120Ω                         │STM32F103│
 │ PA12 TX ├──→[TJA1050]──┬───────────────┬──[TJA1050]←──┤RX PA11  │
 │ PA11 RX ←──┤  模块    │   CANH (双绞) │  │  模块   ├──→TX PA12  │
 │  5V/GND ├──→│          │               │  │         ←──┤5V/GND   │
 └────────┘   └──────────┴───────────────┴──┴─────────┘  └────────┘
                120Ω                                    120Ω
        （总线上只有两端各一个 120Ω；中间节点不要加）
```

接线要点：
1. **CANH 接 CANH、CANL 接 CANL**，不能交叉；用双绞线更好。
2. 两块板**必须共地**（两个 USB 供电时尤其要注意，或用同一 USB HUB/电源）。
3. 两个 120Ω 端电阻分别放在总线**两端**（也就是两个模块上）；只接一个或接三个都会让波形变差。
4. 两节点**波特率必须一致**，否则报错帧狂刷、总线进 Bus-Off。

### 3.3 外设接线

| 板 | 外设 | 引脚（默认，可按实际板改宏） | 说明 |
|---|---|---|---|
| 主机 | 按键 KEY | PA0（内部上拉，外接轻触键到 GND，按下为低） | 每按一次发一帧 0x11；**小蓝丸无板载按键，需外接** |
| 主机 | 串口打印 | PA9=TX / PA10=RX → USB-TTL，115200-8-N-1 | 打印收发记录 |
| 从机 | LED | PC13（小蓝丸板载 LED，低电平点亮） | 收到 0x11 后翻转 |
| 从机 | 串口打印 | 同主机（可选） | 便于调试 |

> 小蓝丸板载件：**LED = PC13**（低电平点亮）、**无用户按键**（要从板上跳线到 PA0 的外接按键）。这些脚在代码里都集中成宏（`LED_PIN` / `KEY_PIN` / `KEY_ACTIVE_LOW`），一行可改。

## 4. 通信协议与参数设计

### 4.1 波特率：500 kbps

| 参数 | 值 | 由来 |
|---|---|---|
| 系统时钟 | 72 MHz | HSE 8MHz × PLL 9 |
| APB1（CAN 挂载） | 36 MHz | 72MHz ÷ 2 |
| Prescaler | 8 | 36MHz ÷ 8 = 4.5 MHz = 1/Tq |
| BS1 / BS2 / SJW | 5Tq / 3Tq / 1Tq | 一位 = 1 + 5 + 3 = 9 Tq |
| 波特率 | 500 kbps | 4.5MHz ÷ 9 = 500 kHz |
| 采样点 | 66.7% | (1+5)/9，接近 CAN 推荐的 75%~87.5%，两节点短距离足够稳 |

> 想跑 STM32 CAN 的最高速 1 Mbps：`Prescaler=4, BS1=5Tq, BS2=3Tq, SJW=2Tq`（野火例程配置）。**先用 500 kbps 跑通再提速**，杜邦线太长时 1 Mbps 容易出错。

### 4.2 报文设计（标准帧，11 位 ID）

| 方向 | ID | IDE | RTR | DLC | Data[0] | 含义 |
|---|---|---|---|---|---|---|
| 主机 → 从机 | `0x111` | 标准 | 数据帧 | 1 | **0x11** | 按键触发的请求 |
| 从机 → 主机 | `0x222` | 标准 | 数据帧 | 1 | **0x22** | 从机的应答 |

- 用不同 ID 区分方向，便于两边都用**硬件筛选器**只收自己关心的帧（比收全部再软件判断更规范）。
- 主机筛选器：只放行 `0x222`；从机筛选器：只放行 `0x111`。掩码模式 `FilterIdHigh/Low` 填 ID，`MaskIdHigh/Low` 填 `0xFFFF`（全匹配）。
- 数据段固定 1 字节，验收时一眼能看出是不是题目要求的 `0x11` / `0x22`。

### 4.3 交互时序

```
主机                          从机
 │  按下 KEY                      │
 ├── 发送 ID=0x111 Data=0x11 ───→ │  收到 → LED 翻转
 │                                ├── 发送 ID=0x222 Data=0x22 ──→
 │  收到 → 串口打印 "RX: 0x22"     │
```

### 5.1 `can.h` 通用接口设计（业务无关）

```c
/* 报文结构 */
typedef struct {
    uint32_t id;        /* 标准帧 11 位 ID */
    uint8_t  ide;       /* 0=标准帧 1=扩展帧 */
    uint8_t  rtr;       /* 0=数据帧 1=远程帧 */
    uint8_t  dlc;       /* 0~8 */
    uint8_t  data[8];
} can_msg_t;

/* 初始化：给定波特率，内部算位时序 */
uint8_t can_init(uint32_t baudrate);                       /* 0=OK */

/* 发送：标准帧，阻塞等邮箱空，返回 0=成功 */
uint8_t can_send(uint16_t std_id, const uint8_t *data, uint8_t len);

/* 接收：非阻塞取一帧；返回 0=取到 1=无数据 */
uint8_t can_recv(can_msg_t *msg);

/* 硬件筛选器：只放行 (id & mask)==(std_id & mask) 的帧 */
uint8_t can_set_filter(uint16_t std_id, uint16_t mask);

/* 中断回调注册：收到帧后由中断上下文调用 */
void can_register_rx_callback(void (*cb)(const can_msg_t *msg));

/* 状态查询与恢复 */
uint8_t can_is_busoff(void);
void    can_recover(void);        /* 退出 Bus-Off 并重启外设 */
```

实现要点：
- 位时序按波特率查表（500k/1M/250k/125k），不把魔数散在业务代码里；
- 接收用 **FIFO0 中断 + 环形队列**，中断里只取帧、回调通知应用，避免在中断里 `printf`；
- 发送检查 `HAL_CAN_AddTxMessage` 的三个邮箱是否占满，满了返回失败而不是死等；
- `can_recover()` 处理 Bus-Off（拔线/波特率不匹配时会进），保证录像时按一下就能恢复。

### 5.2 应用层角色区分

一份工程编译两次，用宏切角色（最省事、最好讲解）：

```c
#define NODE_ROLE_MASTER   1
#define NODE_ROLE_SLAVE    0
/* 在 main.h 或 CMake 里定义：-DNODE_ROLE=NODE_ROLE_MASTER */
```

- **主机**：主循环扫按键（消抖）→ `can_send(0x111, {0x11}, 1)` → 打印 `TX: 0x11`；回调里收到 `0x222` → 打印 `RX: 0x22`。
- **从机**：回调里收到 `0x111` → 打印 `RX: 0x11` → `can_send(0x222, {0x22}, 1)` → `LED_TOGGLE()`。

## 6. 开发流程（分阶段，每阶段有验收）

| 阶段 | 做什么 | 验收标准 |
|---|---|---|
| **0. 准备** | 接线（板↔模块↔总线↔外设）、供电、装串口驱动、确认下载器能用 | 两板都能烧录；串口助手能收到 `printf` 的欢迎信息 |
| **1. 回环自测** | `can_init` 用 `CAN_MODE_LOOPBACK`，自发自收 | 不接模块、不接线也能收回来，证明 `can.c` 收发/筛选器逻辑对 |
| **2. 单节点 + 模块** | 改 `CAN_MODE_NORMAL`，一块板 + 一个模块 | 发送无 Bus-Off；用分析仪/示波器能看到 CANH/CANL 差分波形 |
| **3. 双节点互通** | 两块板两个模块接总线，先做"固定 1s 周期互发" | 两板串口都能打印对方数据，ID/数据完全正确 |
| **4. 按键 + LED** | 主机发送改成按键触发；从机收帧后翻转 LED | 按一次 → 从机 LED 翻转一次 → 主机串口打印 `RX: 0x22` |
| **5. 角色固化** | 编译两次（主机/从机）分别烧录，确认工程组织清晰 | 两板掉电重启后角色不变，行为一致 |
| **6. 异常与健壮性** | 拔一根线、故意改波特率、总线短路 | 能观察到 Bus-Off，`can_recover()` 后恢复通信 |
| **7. 收尾** | 写《第三题开发过程简要说明》、录实操视频、提交到仓库 `test3/` | 提交物齐全，视频里 4 条要求都能看到 |

### 排错顺序（按物理层 → 协议层）

1. **供电与共地**：模块 VCC 实测 5V；两板 GND 相通；模块 STB 接地。
2. **TX/RX 交叉**：MCU 的 TX 要接模块的 **TXD**（不是 RXD），接反是最常见的"发不出"。
3. **端电阻**：万用表量 CANH-CANL 静态电阻，两个 120Ω 并联约 **60Ω**；无穷大说明电阻没接上。
4. **波特率一致**：两板 Prescaler/BS1/BS2 必须一样；不一致会疯狂报错并进 Bus-Off。
5. **筛选器**：掩码/ID 写错会导致"总线有波形但进不了 FIFO"，先改成全通（掩码 0）验证。
6. **引脚重映射**：用 PB8/PB9 必须开 AFIO 时钟并做重映射，否则 PB8/PB9 上根本没有 CAN 信号。

## 7. 验收自测清单

| 题目要求 | 验证方法 | 期望现象 |
|---|---|---|
| 模块化 `can.c`/`can.h` | 看文件：接口只有 init/send/recv/filter/callback/状态 | 换到别的工程只需改引脚宏，业务代码不用动 |
| 主机发 0x11 | 主机按键一次，串口打印 `TX: 0x11` | 从机串口打印 `RX: 0x11` |
| 从机回 0x22 | 主机串口打印 `RX: 0x22` | 数据段确实是 `0x22` |
| 主机串口打印 | 串口助手（115200-8-N-1） | 每按一次出现一组 TX/RX 记录 |
| 按键绑定发送 | 连按 5 次 | 从机串口收到 5 帧，LED 翻转 5 次 |
| 从机 LED 翻转 | 观察 LED | 每收到一帧翻转一次（亮→灭→亮…） |

## 9. 已定方案 + 待你确认的 3 件事

**已定（由我拍板）**：

| 项 | 结论 | 理由 |
|---|---|---|
| CAN 引脚 | **PA11(RX) / PA12(TX)，CAN1 默认，无需重映射** | 小蓝丸标准脚；避开部分蓝丸 PB9 焊接的红外接收头；不用 USB（烧录走 SWD、串口走 PA9/PA10），PA11/PA12 空着当 CAN 用 |
| 波特率 | **500 kbps** | 杜邦线短距最稳，两个同型号模块一致即可；跑通后可演示 1 Mbps |
| 角色切换 | **一份工程编译两次**（`-DNODE_ROLE=MASTER/SLAVE`） | 单份源码/单个 .ioc，两板只差一个宏，维护和提交最省事；双工程会重复整个 CubeMX 树 |
| 从机 LED | **PC13（小蓝丸板载，低电平点亮）** | 无需额外接线 |
| 主机按键 | **PA0 + 外接轻触键到 GND（内部上拉，按下为低）** | 小蓝丸无板载按键，需外接一个 |

**已确认**：两块板都是小蓝丸（STM32F103C8T6）+ 两个一模一样的野火小智【CAN收发器】模块；模块 3 孔端子顺序 = **CANH / CANL / GND**。

**只剩最后 1 点**：主机外接的轻触键接 **PA0** 可以吗（或你指定一个空闲脚），以及你有没有这个外接按键？确认后我就按 test2 的规范（CubeMX + CMake + HAL + OpenOCD 脚本）把 `test3/` 代码写出来，再补正式说明文档。
