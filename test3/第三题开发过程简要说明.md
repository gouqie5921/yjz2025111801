# 开发过程简要说明 — CAN 通信（第三题）

> 考核题：软件第三题《CAN 通信》
> 目标：用模块化思路写一对 `can.c`/`can.h` 通用 CAN 收发函数；两块 STM32F103C8T6 分别作主机/从机；
> 主机按键触发发送 `0x11`，从机收到后回 `0x22` 并翻转 LED，主机把收到的数据打印到串口助手。
> 本说明对应工程目录 `test3/`（Core/Src：can.c、main.c、gpio.c、usart.c、stm32f1xx_hal_msp.c、stm32f1xx_it.c）。

## 2. 材料与硬件

### 2.1 材料清单

| 类别 | 物品 | 规格 | 数量 |
|---|---|---|---|
| 主控 | STM32F103C8T6 开发板 | 蓝丸最小系统板（HSE 8MHz → 72MHz） | 2 |
| CAN 收发器 | 野火小智【CAN收发器】模块 | 高速 CAN（TJA1050 类），丝印 `VIO/5V/GND/TXD/RXD` + 3 孔端子 `CANH/CANL/GND` | 2 |
| 终端电阻 | 120Ω 电阻 | 1/4W，跨接 CANH-CANL | 2 |
| 供电 | 12V 电池 + 降压模块 | 降压输出调到 5.0~5.2V（带载实测） | 1 套 |
| 串口 | USB 转 TTL（CH340） | 3.3V/5V 均可，115200 | 1~2 |
| 下载器 | ST-Link V2（克隆） | SWD，配 OpenOCD 烧录 | 1 |
| 按键 | 杜邦线（模拟按键） | 主机 PA0 瞬间碰 GND 当一次按下 | 1 |
| 指示灯 | 板载 LED | 从机 PC13，低电平点亮 | — |

> 说明：手头没有独立按键模块，题目要求"发送与按键绑定"，故用 PA0（内部上拉）+ 杜邦线对 GND 瞬间短接模拟一次按下；换成轻触按键接 PA0-GND 效果相同，代码无需改。

### 2.2 引脚分配

| 功能 | 引脚 | 说明 |
|---|---|---|
| CAN1_RX | **PA11** | 上拉输入，默认映射 |
| CAN1_TX | **PA12** | 复用推挽输出，默认映射 |
| 主机按键 KEY | **PA0** | 内部上拉，按下=低 |
| 从机 LED | **PC13** | 板载 LED，低电平点亮 |
| 串口 USART1 | PA9=TX / PA10=RX | 115200-8-N-1 |
| 烧录/调试 | PA13=SWDIO / PA14=SWCLK | ST-Link + OpenOCD |

**CAN 引脚选择理由**：CAN1 默认脚就是 PA11/PA12，**无需重映射**，最省事；本工程不使用板载 USB（烧录走 SWD、串口走 PA9/PA10），所以 PA11/PA12 空出来当 CAN 用没有影响；同时避开了部分蓝丸在 **PB9 焊有红外接收头**（会往总线加负载）的隐患。

### 2.3 接线

**(1) 每块板 ↔ 模块（模块丝印 5 个脚）**

| 模块丝印 | 接到蓝丸 | 说明 |
|---|---|---|
| `VIO` | **3V3** | 逻辑电平参考，**必须接**；不接或误接 5V → 逻辑侧不工作/电平判错 → 帧发不上总线 |
| `5V` | 5V | 收发器工作电源 |
| `GND` | GND | 共地 |
| `TXD` | **PA12** | MCU 发 → 模块收（注意别接反） |
| `RXD` | **PA11** | 模块发 → MCU 收 |

**(2) 总线（模块顶部 3 孔端子，丝印 `CANH / CANL / GND`）**

```
模块A.CANH ────── 模块B.CANH
模块A.CANL ────── 模块B.CANL
模块A.GND  ────── 模块B.GND      ← 并接两块板的 GND（共地）

每个模块端子上跨接 1 个 120Ω（CANH-CANL），总线两端共 2 个
```


**(3) 外设**
- 主机：PA0 ↔ 杜邦线 → GND（按一次发一帧）；PA9/PA10 → USB-TTL。
- 从机：观察 PC13 板载 LED（收到一帧翻转一次）；如需打印同样接 PA9/PA10 → USB-TTL。
- 烧录：SWDIO→PA13、SWCLK→PA14、GND→GND、3V3→3V3。

### 2.4 供电方案

```
12V 电池 ──> 降压模块(输出调到 5.0~5.2V，带载实测)
                 OUT+ 5V ─┬─> 蓝丸A 5V      ├─> 蓝丸B 5V
                          ├─> 模块A 5V      └─> 模块B 5V
                 OUT- GND ┬─> 蓝丸A/B GND  ├─> 模块A/B GND
                          └─> USB-TTL GND（共地）
```
- 一路 5V 供两块板 + 两个模块，**全部共地**；总电流约 300~400mA（两板各 50~100mA + 两模块各约 70mA），降压模块余量充足。
- USB-TTL **只接 TX/RX/GND，不接它的 VCC**，避免与 5V 电源双电源冲突。
- 模块 `VIO` 单独接各板的 **3V3**。

## 3. 通信协议与参数设计

### 3.1 波特率：500 kbps

| 参数 | 值 | 由来 |
|---|---|---|
| CAN 时钟 | APB1 = 36MHz | 72MHz ÷ 2 |
| Prescaler | 8 | 36MHz ÷ 8 = 4.5MHz = 1/Tq |
| BS1 / BS2 / SJW | 5Tq / 3Tq / 1Tq | 一位 = 1 + 5 + 3 = 9 Tq |
| 波特率 | 500 kbps | 4.5MHz ÷ 9 = 500 kHz |
| 采样点 | 66.7% | (1+5)/9，短距离两节点足够稳 |

（寄存器实测 `BTR = 0x00240007`：BRP=7→分频 8、TS1=4→BS1=5、TS2=2→BS2=3，与设计一致。）

### 3.2 报文设计（标准帧，11 位 ID）

| 方向 | ID | IDE | RTR | DLC | Data[0] |
|---|---|---|---|---|---|
| 主机 → 从机 | `0x111` | 标准 | 数据帧 | 1 | `0x11` |
| 从机 → 主机 | `0x222` | 标准 | 数据帧 | 1 | `0x22` |

### 3.3 交互时序

```
主机                                       从机
  │  PA0 对 GND 短接一次                       │
  ├─ 发 ID=0x111 Data=0x11 ───────────→ 收到 → 回 ID=0x222 Data=0x22 + 翻转 PC13 LED
  ←─ 收到 0x22 → 串口打印 "[M] CAN RX: id=0x222 dlc=1 d0=0x22"
```

### 3.4 筛选器策略

- 默认配置为"**全收**"（掩码 0），由应用层按 ID + 数据软件过滤 —— 实现简单、不依赖筛选器位布局，最稳。
- 同时提供 `can_set_filter(std_id, mask)`（32 位掩码模式，标准 ID 位于筛选字 bit[31:21]），需要硬件过滤时可直接用。

### 4.1 `can.h` 通用接口

```c
typedef struct { uint32_t id; uint8_t ide; uint8_t rtr; uint8_t dlc; uint8_t data[8]; } can_msg_t;

uint8_t can_init(uint32_t baudrate);                                   /* 125k/250k/500k/1M，内部算位时序 */
uint8_t can_send(uint16_t std_id, const uint8_t *data, uint8_t len);   /* 标准帧 */
uint8_t can_recv(can_msg_t *msg);                                      /* 从环形队列取一帧 */
void    can_poll(void);                                                /* 轮询接收（主循环调用） */
uint8_t can_set_filter(uint16_t std_id, uint16_t mask);                /* 硬件筛选器 */
void    can_register_rx_callback(void (*cb)(const can_msg_t *msg));    /* 收帧回调 */
uint8_t can_is_busoff(void);
void    can_recover(void);
```

### 4.2 实现要点

- **位时序查表**：波特率 → (prescaler, BS1, BS2, SJW)，魔数集中在 `can.c`，上层只传波特率。
- **接收双保险**：FIFO0 中断 + 环形队列（深度 8）；同时在主循环调用 `can_poll()` 轮询取空 FIFO0。两者并用不会重复派发（谁先取走算谁的），既快又不会漏帧。
- **发送**：先等空闲邮箱（≤10ms），`HAL_CAN_AddTxMessage` 入邮箱，再等发送完成；`AutoRetransmission = ENABLE`。
- **异常处理**：`can_is_busoff()` 读 `CAN1->ESR` 的 BOFF 位；主循环检测到 Bus-Off 时只打印一次提示并 `can_recover()`（Stop → ResetError → Start），恢复后打印 `recovered`。
- **单板自测开关**：`can.h` 顶部 `#define CAN_MODE_SEL CAN_MODE_NORMAL`，改成 `CAN_MODE_LOOPBACK` 即可一块板自发自收。
- **调试寄存器打印**：`main.c` 的 `can_dump_regs()` 在 init/rx/tx 三处打印 MCR/MSR/TSR/RF0R/IER/ESR/BTR（`CAN_DEBUG_DUMP` 可关闭），是本项目定位总线问题的关键手段。

### 4.3 角色切换（一份工程，改一行源码）

```c
/* Core/Src/main.c 顶部 */
#define NODE_ROLE  NODE_ROLE_MASTER      /* 从机改成 NODE_ROLE_SLAVE */
```
不用改任何 CMake 参数，改完直接点编译按钮 → 烧录。流程：保持 `MASTER` 编译烧板A；改成 `SLAVE` 编译烧板B。

### 4.4 应用层逻辑

- **主机**：主循环扫 PA0（20ms 消抖）→ `can_send(0x111,{0x11},1)` → 打印 `[M] CAN TX: 0x11`；收到帧 → 打印 `[M] CAN RX: id=... dlc=... d0=...`。
- **从机**：收到 `0x111` 且 `DLC=1`、`Data[0]=0x11` → `can_send(0x222,{0x22},1)` + `led_toggle()`（PC13）→ 打印 `[S] CAN RX/TX`。

### 4.5 串口输出格式（便于验收）

```
=== 3rd: CAN comm ===
[role] MASTER
[can ] 500kbps, ID 0x111->0x222
[reg]init MCR=... MSR=... TSR=... RF0R=... IER=... ESR=... BTR=...
[key ] touch PA0 to GND to send 0x11
[M] key
[M] CAN TX: 0x11
[reg]tx ...
[M] CAN RX: id=0x222 dlc=1 d0=0x22
```

## 6. 开发中遇到的问题与排查（真实记录）

### 问题 1：`VIO` 是什么？没接就发不出去
- 现象：模块能上电，但主机发帧后总线上什么都没有。
- 原因：`VIO` 是**逻辑电平参考**（不是总线电源）。它决定 `TXD/RXD` 按多少伏判高低。蓝丸是 3.3V 逻辑，`VIO` 悬空则逻辑侧无参考、收发不工作；若误接 5V，则模块按 5V 判 `TXD`，3.3V 高电平可能被判成低。
- 解决：`VIO` 接蓝丸 **3V3**，`5V` 仍接 5V。

### 问题 2：`BUS-OFF`
- 现象：串口打印 `[can ] BUS-OFF ...`。
- 原因：CAN 正常模式下，发出的帧**必须被总线上另一个节点 ACK**；没人应答 → 发送错误计数 TEC 每帧 +8，涨到 255 即进 Bus-Off。
- 排查顺序（按物理层优先）：① 第二个节点是否上电并在运行；② CANH↔CANH、CANL↔CANL 是否接对；③ 两块板是否共地；④ 模块 5V/VIO 是否有电；⑤ 端电阻。
- 解决：补上 120Ω 端电阻、接好 VIO、确认从机在运行后，Bus-Off 消失。

### 问题 3：单板测试必然 Bus-Off
- 原因：正常模式需要第二个节点 ACK，单板不可能成功。
- 解决：单板自测改用回环模式（`CAN_MODE_SEL = CAN_MODE_LOOPBACK`），不需要第二个节点。

### 问题 4：改了代码但编译失败，烧进去的是旧固件
- 现象：单板回环测试"也没有 RX"，一度以为接收中断有问题。
- 真因：改回环开关时误把 `main.c` 里的 `#define NODE_ROLE NODE_ROLE_MASTER` 覆盖成了 `#define CAN_MODE_SEL ...`，导致 `NODE_ROLE` 未定义、**编译直接报错**（`error: 'NODE_ROLE' undeclared`）；而烧录用的是上一次成功编译的旧 elf（正常模式），所以回环当然收不到。
- 解决：恢复角色宏（回环开关统一放到 `can.h`）；并约定用**开机是否打印 `[reg]init`** 判断新固件是否真的烧进去了。
- 教训：改完代码先确认编译成功，再看串口新输出的标志行，避免"测的是旧固件"。

### 问题 5：两个模块的 120Ω 端电阻都没接
- 原因：ISO11898 高速 CAN 要求总线**两端各一个 120Ω**，跨接在 CANH 与 CANL 之间。没有端接时差分电平在采样点不稳定，直接表现为 ACK 错误 / Bus-Off。
- 解决：两个模块端子上各跨接一个 120Ω（共 2 个）；断电实测 CANH-CANL ≈ **60Ω**。

### 问题 6：用寄存器把故障定位到"总线层"（关键方法）
- 回环自测（证明驱动正常）：
  ```
  [reg]init BTR=40240007  → bit30 LBKM=1（回环），分频/位时序=500kbps
  [reg]tx   TSR=1C000003  → TXOK0=1（发送成功）、ESR=00000000（无错误）
            RF0R=0        → 帧已进 FIFO 并被取走
  [M] CAN RX: id=0x111 dlc=1 d0=0x11        ← 自发自收成功
  ```
- 正常模式双机（定位到总线层）：
  ```
  [reg]tx   BTR=00240007  → LBKM=0（正常模式）
            ESR=FF000013  → 低 3 位 LEC=0b011=3 = ACK Error（无人应答）
            TSR=19000004  → 邮箱未释放（帧卡在重传）
            MSR=00000100  → TXM=1，已失步
  ```
- 结论：`ESR` 的 LEC=3 直接指出"没人 ACK"，把问题从软件排除到硬件总线，省去大量盲目试错。
