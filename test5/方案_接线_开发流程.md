# 第五题《二自由度舵机云台》— 方案 · 接线 · 开发流程

> 考核题：软件第五题《二自由度舵机云台》
> 要求：① 分"舵机执行端 / 主控端"两个模块，各一套程序，**无线（蓝牙）通信**；
> ② 两个电位器分别控制水平偏转、俯仰；③ MPU6050 放面包板上，拿起来转动 → 云台跟随（水平旋转 + 俯仰）；
> ④ 两种控制方式在同一工程内**实时切换**；⑤ 用 **FreeRTOS**。
> 提交：程序设计说明（重点）、**与 AI 对话的关键内容截图**（单独文件夹）、项目文件、演示视频。

> ⚠️ **本文是开发前的设计草案（前期方案）**，用于记录思路与开发流程；
> **最终实现以 [`第五题程序设计说明.md`](第五题程序设计说明.md) 为准。**
> 实现过程中有 3 处对草案做了修改，原因见文末「§附：实现与草案的差异」。

## 0. 系统架构

```
                 蓝牙（HC-05 主）              蓝牙（HC-05 从）
┌───────────────────────┐   ～～～～～～～>   ┌──────────────────────┐
│      主控端            │   数据包 20ms      │       执行端          │
│  (STM32F103C8T6)      │   pan/tilt/mode    │  (STM32F103C8T6)     │
│  · 电位器×2 → ADC      │                    │  · TIM3_CH1 → 水平舵机 │
│  · MPU6050 → I2C      │                    │  · TIM3_CH2 → 俯仰舵机 │
│  · 模式按键 → EXTI/扫键 │                    │  · 舵机平滑 + 限速     │
│  · 蓝牙 USART1 → 发送   │                    │  · 蓝牙 USART1 → 接收   │
│  · FreeRTOS            │                    │  · FreeRTOS           │
└───────────────────────┘                    └──────────────────────┘
      手持/桌面                                    装在云台支架上
```

- **主控端**：采集两种控制源（电位器 / 陀螺仪），按键实时切换，按固定协议通过蓝牙发角度指令。
- **执行端**：解析数据包，平滑驱动两个 SG90（50Hz PWM）。
- 两端各自独立工程（两个 `.ioc`、两套 `Core/` 代码），放在仓库 `test5/master/` 与 `test5/slave/`。

## 1. 物料与引脚规划

### 1.1 主控端（Master）

| 功能 | 引脚 | 说明 |
|---|---|---|
| 电位器 1（水平偏转） | **PA1** = ADC1_IN1 | 滑臂接 PA1，两端接 3V3 / GND |
| 电位器 2（俯仰） | **PA4** = ADC2_IN4 | 同上（最终用独立的 ADC2，见文末差异说明） |
| MPU6050 SCL | **PB6** = I2C1_SCL | 模块放面包板上，用长杜邦线连回 |
| MPU6050 SDA | **PB7** = I2C1_SDA | |
| 蓝牙 HC-05 | **PA9(TX) / PA10(RX)** = USART1 | 115200（或 9600，两端一致） |
| 模式按键 | **PA0** | 内部上拉，按下=低；切换 电位器↔陀螺仪 |
| 状态灯 | **PC13** | 电位器模式闪 1 下 / 陀螺仪模式闪 2 下 |
| 调试串口（可选） | PA2/PA3 = USART2 | 接 USB-TTL 打印调试信息 |
| 烧录 | PA13/PA14 | SWD |

### 1.2 执行端（Slave）

| 功能 | 引脚 | 说明 |
|---|---|---|
| 水平舵机信号 | **PA6** = TIM3_CH1 | 50Hz，0.5~2.5ms ↔ 0~180° |
| 俯仰舵机信号 | **PA7** = TIM3_CH2 | 与水平舵机**同一个定时器**，天然同频 |
| 蓝牙 HC-05 | **PA9(TX) / PA10(RX)** = USART1 | 与主控端一致 |
| 状态灯 | **PC13** | 收到数据闪烁 / 通信超时报警 |
| 调试串口（可选） | PA2/PA3 = USART2 | |
| 烧录 | PA13/PA14 | SWD |

### 1.3 接线表（逐根）

**主控端**
```
电位器1:  1脚→3V3   2脚(滑臂)→PA1   3脚→GND
电位器2:  1脚→3V3   2脚(滑臂)→PA4   3脚→GND
MPU6050:  VCC→5V(模块板载LDO)  GND→GND  SCL→PB6  SDA→PB7
HC-05:    VCC→5V   GND→GND   TXD→PA10   RXD→PA9      ← 注意交叉
按键:     PA0 ── 按键 ── GND
SWD:      SWDIO→PA13  SWCLK→PA14  GND/3V3
```

**执行端**
```
水平舵机: 橙(信号)→PA6   红→5V(独立足流)   棕→GND
俯仰舵机: 橙(信号)→PA7   红→5V(独立足流)   棕→GND
HC-05:    VCC→5V   GND→GND   TXD→PA10   RXD→PA9
SWD:      SWDIO→PA13  SWCLK→PA14
```

### 1.4 供电（关键！）

```
12V 电池 ──> 降压模块(5V~6V, ≥2A) ──┬─> 两个 SG90 的 5V
                                    └─> 执行端蓝丸 GND / 舵机 GND（共地，粗线）
执行端蓝丸: 用 Micro-USB 充电线供电（5V）
主控端:     Micro-USB 充电线供电；MPU6050 用 5V（GY-521 板载 LDO）；HC-05 用 5V
```
- 两个 SG90 同时动作瞬时电流可达 **1A 以上**，必须独立足流 5V + **共地**（第二题踩过的坑）。
- 舵机电源线就近并 **470µF 电解 + 0.1µF**，抑制启停尖峰。
- HC-05 的 `RXD` 接 MCU 的 `TX`（交叉），模块 TXD 输出 3.3V 电平，F103 引脚可直连。

## 2. 通信协议设计（参考 keysking 的"简易数据包解析"思路）

固定长度短帧 + 校验，执行端用**状态机逐字节解析**（放在 UART 中断里最稳）：

```
┌──────┬──────┬──────┬──────────┬──────────┬──────────┬────────┐
│ 0xAA │ 0x55 │ LEN  │  pan_H/L │ tilt_H/L │  mode    │  CHK   │
│ 帧头1│ 帧头2│ =7   │ 2 字节   │ 2 字节   │ 1 字节   │ 1 字节 │
└──────┴──────┴──────┴──────────┴──────────┴──────────┴────────┘
                          CHK = LEN ^ pan_H ^ pan_L ^ tilt_H ^ tilt_L ^ mode
```
- `pan` / `tilt`：0~1800（0.1° 分辨率），执行端除以 10 得到角度。
- `mode`：0=电位器模式，1=陀螺仪模式（执行端可据此切换 LED 指示）。
- 发送周期 **20ms**（50Hz）；丢帧不补发，执行端做**超时保护**（>200ms 无帧 → 舵机保持/回中并报警）。

**为什么不用文本协议**：蓝牙透传下二进制定长帧解析快、不易错位；配合帧头 + 校验，抗干扰好。

## 3. MPU6050 姿态解算（主控端）

| 量 | 来源 | 说明 |
|---|---|---|
| **俯仰角 pitch** | 加速度计 + 陀螺仪**互补滤波** | `angle = 0.98×(angle + gyro×dt) + 0.02×accel_angle`，加速度计提供绝对基准（重力），不漂移 |
| **水平偏转 yaw（pan）** | 陀螺仪 Z 轴**积分** | 手转面包板时跟随；需**开机零偏校准**（静置 1s 求平均作为 bias）并在切换模式时**清零基准** |

要点：
1. **上电零偏校准**：静止 1 秒采样陀螺仪均值作为 bias，否则会持续漂移。
2. **互补滤波系数** 0.98 可按手感调整（越小越信加速度计，越大越平滑但漂移明显）。
3. **角度映射**：把 `yaw`（可累积超过 ±180°）裁剪到 0~180°，映射成云台 `pan`；`pitch` 直接映射 `tilt`（注意安装方向/正负号，必要时取反）。
4. 陀螺仪放在**面包板**上，用长杜邦线连回主控端——这样"拿起面包板转动"就是旋转传感器本体。

## 4. FreeRTOS 任务划分

### 4.1 主控端（Master）

| 任务 | 优先级 | 周期 | 职责 |
|---|---|---|---|
| `SendTask` | **High** | 20ms | 组帧 + UART 发送（互斥锁保护）；超时/心跳统计 |
| `SensorTask` | AboveNormal | 10ms | 读 MPU6050（I2C）→ 互补滤波出 pitch/yaw → 写入共享姿态结构 |
| `AdcTask` | AboveNormal | 20ms | 读两路电位器（多次平均 + 一阶低通）→ 映射成 0~1800 |
| `KeyTask` | Normal | 20ms | 扫按键（消抖）→ 切换控制模式；切换时**清零 yaw 基准 / 复位滤波** |
| `LedTask` | Low | 500ms | 心跳灯 + 模式指示（闪 1 / 闪 2） |

通信：`sensor/adc/key` 写共享结构（互斥锁或双缓冲）→ `SendTask` 统一组帧发送。

### 4.2 执行端（Slave）

| 任务 | 优先级 | 周期 | 职责 |
|---|---|---|---|
| `ServoTask` | **High** | 20ms | 从队列取目标角度 → 限速平滑（slew rate）→ 写 CCR |
| `ParseTask` | AboveNormal | 事件/10ms | 处理 UART 环形缓冲 → 状态机解析 → 校验 → 入队（也可直接在中断里解析后入队） |
| `TimeoutTask` | Normal | 100ms | 监测最后收帧时间；超时→安全动作（回中/保持）+ LED 报警 |
| `LedTask` | Low | 500ms | 状态指示（有数据闪 / 超时快闪） |

要点：**UART 中断只做入环形缓冲**，解析放任务里；舵机限速（例如每 20ms 最多变化 3°）避免突跳。

## 6. 蓝牙 HC-05 配置（AT 指令，用 USB-TTL）

1. 接线：USB-TTL 的 TX→HC-05 RXD、RX→HC-05 TXD、5V/GND；
2. **按住模块上的 KEY/EN 键再上电**进入 AT 模式（指示灯慢闪）；
3. 串口助手 **38400-8-N-1**（经典 HC-05 的 AT 模式波特率），发送：
```
AT                 → OK
AT+ROLE=1          → 主控端那只要设成主机(Master)
AT+ROLE=0          → 执行端那只要设成从机(Slave)
AT+UART=115200,0,0 → 波特率 115200（两端都要设成一样）
AT+CMODE=1         → 任意地址连接
AT+PSWD=1234       → 配对码（两端一致）
AT+NAME=GYRO_M     → 起个名字方便识别
```
4. 退出 AT 模式重新上电，两模块会自动配对连接（从机指示灯常亮=已连接）。
> 若嫌麻烦：**保持默认 9600** 也行，只要两端 MCU 的 USART 都是 9600、发送周期放宽到 30ms 即可。

## 附：实现与草案的差异（3 处）

| # | 草案写的 | 最终实现 | 为什么改 |
|---|---|---|---|
| 1 | 两个电位器都挂在 **ADC1** 上（PA1=IN1、PA4=IN4），多通道扫描 | **ADC1(PA1) 与 ADC2(PA4) 各自独立、单通道连续转换**，不用扫描、不用 DMA | CubeMX 生成的多通道扫描配置有坑（`NbrOfConversion=1` 却配了 Rank1/Rank2，PA4 从来没被采样）；两个独立 ADC 各自读 DR 更简单，也不会互相抢总线 |
| 2 | 串口用 **UART 接收中断 + 环形缓冲**，解析放任务里 | **任务内轮询接收**（`HAL_UART_Receive()` 超时 5ms）+ 状态机解析 | ① CubeMX 生成的 USART1 中断优先级是 0，而 FreeRTOS 要求调用 RTOS API 的中断优先级必须 ≥ 5，用中断还得在代码里强制改 NVIC；② 450 B/s 的速率轮询完全够用；③ 轮询方案里显式处理了 ORE 溢出清标志（HAL 轮询接收最容易踩的坑） |
| 3 | 失联后"舵机保持**或回中**并报警" | 失联**只保持当前位置**，LED 快闪报警 | 云台端着东西，失联时突然回中/松脱比停在原地更危险；保持不动是更安全的故障策略 |

另外两处**参数**上的落实（草案只写了大致量级）：

- 舵机限速：草案"每 20ms 最多变化 3°" → 实现为 **300°/s**（即 20ms 最多 6°），兼顾跟手与保护齿轮；
- 蓝牙波特率：草案提到"115200 或保持 9600" → 实现统一用 **115200**（HC-05 必须 `AT+UART=115200,0,0` 改过，出厂 9600 不改一定通信不上）。
